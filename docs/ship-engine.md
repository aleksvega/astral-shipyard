# Движок сборки кораблей

Борт собирается не из готовой модели, а из трёх независимых слоёв. Один и тот
же seed всегда даёт тот же корабль, поэтому каталог воспроизводим и проверяем.

| Слой | Файл | Что задаёт |
|---|---|---|
| Стиль фракции | `lib/three/ship/style.ts` | палитра, материалы, язык деталей и веса частей |
| Класс | `lib/three/ship/classes.ts` | пропорции, оснастку, число ярусов портов, «богатство» |
| ДНК (seed) | `lib/three/ship/generate.ts` | разброс чисел и выбор конкретных частей |

## Как это работает по шагам

1. `generateShip({ seed, faction, classId })` берёт стиль и класс.
2. Профиль корпуса класса разбрасывается джиттером (длина, ширина, киль,
   седловатость палубы) — в пределах, заданных классом.
3. Ставится корпус: `buildLoftedHull` + палуба, гондольное брюхо, пояса.
4. `buildSockets` считает **сокеты** — точки сочленения на реальной поверхности.
5. Части выбираются по весам стиля и садятся в сокеты.
6. Добавляются классовый обвес, реактор, розы и гирлянды.
7. Возвращается `ShipDNA`: размеры, список частей, статы и подпись.

## Сокеты: почему части не висят в воздухе

Сокет — это не «примерно там». У него есть:

- `pos` — точка на обшивке, полученная рейкастом луча снаружи внутрь;
- `dir` — наружное направление, которым разворачивается часть;
- `up` — верх части (для вертикальных мест — ось Z);
- `size` — максимальный типоразмер, который сюда влезает.

Правило простое: **ни одна часть не ставится по средней ширине корпуса**.
Ширина на высоте палубы и на высоте порта разная из-за завала борта
(tumblehome), поэтому и пушки, и розы, и броневые плиты берут X из
`hullSurfaceHit(hull, side, y, z)`.

Посадка выполняется `seatPart(socket, part, sink, scale)`:

- позиция = точка сокета плюс утопление вдоль `dir` (часть входит в корпус);
- разворот = `socketQuaternion(socket)`: локальный −Z части смотрит наружу;
- масштаб = ширина корпуса / эталон, поэтому детали растут вместе с бортом.

Соглашение о моделировании части: **нос/выступ в −Z, верх в +Y, начало
координат на стыке**. Тогда одна и та же часть годится и на нос, и на борт,
и на корму.

## Типоразмеры

| Тип | Корабль | Что влезает |
|---|---|---|
| 1 | шлюп | мелкие фигуры, один ярус портов |
| 2 | фрегат, галеон, таран | купола, сопла, кормовые башни |
| 3 | дредноут | тяжёлые части, два яруса портов |

Часть с `size: 3` не встанет на шлюп: `pickPart` фильтрует по типоразмеру
слота. Это единственное место, где проверяется совместимость, — добавлять
проверки в сами части не нужно.

## Каталог частей

`lib/three/ship/parts.ts` — список `PartDef`:

```ts
{ id: 'griffon', slot: 'bow', size: 1, weight: 5, build, stats: { energy: 0.05 } }
```

- `slot` — куда садится: `bow | stern | engine | deck`;
- `size` — минимальный типоразмер корабля;
- `weight` — вес внутри стиля (не глобальный: стиль задаёт свои веса);
- `build(mats, rng)` — геометрия в локальной системе части;
- `stats` — вклад в характеристики (таран, скорость, броня, энергия).

Новая часть = одна запись в `PARTS` и одна функция `build`. Никаких правок
генератора.

## Классовый обвес

`lib/three/ship/kits.ts` добавляет то, что читается издалека, когда пропорций
мало: броневой форштевень тарана, лапы и клешни краба, верхнюю батарею
дредноута. Обвес тоже садится через рейкаст.

## Фракции и школы корпуса

Фракция задаёт не палитру, а **школу постройки** (`lib/three/ship/school.ts`):
школа меняет сечение корпуса (`bilgeExp`), число точек кольца (`ringPoints`,
отсюда гранёность), завал борта (`tumblehome`), асимметрию обшивки, высоту
палубы и длину носа, а сверху добавляет фракционный обвес
(`addSchoolKit`/`addSchoolTrim`).

| Фракция | Школа | Что видно на борту |
|---|---|---|
| Лига | `gondola` | круглое сечение, 7 точек кольца, лакированный корпус, латунь |
| Империя | `wedge` | 3 точки кольца → плоские фасетки, завал 0.25, хребет, рубка, спонсоны, сопла, без парусов |
| Орки | `scrap` | 4 точки, асимметрия 0.13, ржавые накладные заплаты, бронепояс, труба, таран |
| Гоблины | `spike` | 5 точек, завал 0.7, костяные шипы по бортам и дорсальный ряд лезвий |
| Нейтралы | `civil` | 6 точек, ровный серый корпус, тяжёлые надстройки, квадратный рангоут |

Паруса выключаются стилем: если в `sailPlans` только `none`, генератор не
ставит мачты вообще.

Класс поверх школы даёт пропорции, число мачт, ярусы орудий и тир; seed даёт
детерминированный разброс и выбор частей. Один seed → одна и та же подпись
(`ShipDNA.signature`), поэтому витрина `/shipyard` воспроизводима.

## Движок как отдельный слой

Сборка вынесена в `lib/three/ship/engine/` — это переносимая часть: она не знает
про игру, сцену и бой. Четыре контракта, на которых держится всё остальное.

**1. Блюпринт (`engine/spec.ts`)** — корабль как данные: `faction`, `classId`,
`seed`, плюс явные выборы `bow`, `stern`, `engine`, `deck[]`, `sails`, `masts`,
`gunRows`, `palette`. `generateShip({ blueprint })` накладывает их поверх весов
стиля; чего нет в блюпринте, то генератор решает сам. `picksOf()` разворачивает
блюпринт в список выборов для сметы, `describeBlueprint()` — в строку для UI.

**2. Смета (`engine/budget.ts`)** — чистые правила без графики: слот, типоразмер,
количество на слот, суммарная масса. `rulesForScale(scale)` выводит лимиты из
размера корпуса, `evaluateBuild(picks, catalog, rules)` возвращает `ok`, массу и
человеческие ошибки. Это основа редактора: невалидную сборку движок не соберёт.

**3. Палитра (`engine/paint.ts`)** — цвет как канал, а не как свойство меша:
`hull`, `deck`, `trim`, `sail`, `glass`, `core`, `dark`, `lamp`, `wood`. Части
берут канал, `applyPalette()` заливает каналы, `readPalette()` снимает текущую
схему. Поэтому корпус перекрашивается без пересборки геометрии, а
`paletteFromHints(['red'])` превращает слово из описания в наложение красок.

**4. Посадка на поверхность (`engine/mount.ts`)** — `probeHullSurface()` пускает
луч в обшивку и возвращает точку, нормаль наружу и касательную вдоль борта;
`mountFlush()` садит деталь по этой нормали, `scatterOnHull()` раскладывает
накладки по борту. Так заплаты и бронеплиты прилегают к гранёному корпусу, а не
висят параллельно оси.

**Сборка по описанию.** `engine/text.ts` разбирает «имперский дредноут без
парусов, две башни, сид 12, алый» в те же поля блюпринта: фракция, класс, seed,
паруса, ярусы, число мачт, слова-краски. Разбор на стемах, без модели языка —
зато детерминированный и покрытый тестами. Витрина умеет это напрямую:

```
http://localhost:3000/shipyard?text=имперский дредноут без парусов, две башни, сид 12, алый
```

В правой колонке печатается, что именно распознано, — видно, где парсер
промолчал, а где понял.

## Что проверять после правок

1. `npx tsc --noEmit` — 0 ошибок.
2. `npm test` — 38/38 (механика + движок кораблей).
3. `npx next build` — OK.
4. `/shipyard` — 20 карточек, 0 ошибок консоли.
5. `?text=…` — один борт, в списке распознанные поля, 0 ошибок консоли.
6. Глазами: части сидят на поверхности, стволы не торчат из воздуха, силуэты
   классов различаются.

## Куда расти

- редактор: UI поверх готовых `picksOf` + `evaluateBuild` (смета уже считает
  ошибки), переключение частей в слоте без пересборки корпуса;
- бюджеты: сейчас лимиты выведены из масштаба класса; добавить цену/редкость;
- LOD: дальние борта рисуются упрощённым набором (корпус + силуэтный обвес);
- витрина: убрать перспективный разъезд рядов (длинный фокус уже стоит),
  номера бортов держать в HTML-списке, а не спрайтами в 3D;
- пушки: на дистанции витрины ствол не читается — нужен либо крупный план
  слота, либо силуэтная нашлёпка порта.
