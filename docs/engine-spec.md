# Спецификация движка кораблей «Астральный Рубеж»

Версия: 1.0 (13.11.2026). Статус: живой документ, меняется вместе с кодом.
Заменяет устные договорённости: если код и этот файл расходятся — прав код, файл
правится тем же коммитом.

## 1. Назначение и границы

Движок собирает борт из данных: фракция, класс, сид, слоты, паруса, палитра.
Один и тот же вход даёт один и тот же корабль — геометрию, подпись, PNG и GLB.

**Делает:**

- детерминированную сборку из блюпринта (данные) или описания словами;
- проверку сборки сметой: слот, типоразмер, вместимость, масса;
- раскраску по каналам без пересборки геометрии;
- посадку деталей по нормали обшивки (сокеты, накладки, стволы);
- выгрузку PNG-кадра, JSON-спеки и GLB с запечёнными текстурами;
- витрину флотов: N бортов одной школы в одном кадре.

**Не делает:**

- не рисует финальный арт руками художника (процедура + CC0-текстуры);
- не гарантирует watertight-тела (обшивка открытая, `DoubleSide`);
- не заменяет игровую логику: урон, ИИ, экономика живут в `lib/game`.

## 2. Рынок и отличие

Соседи (`exoticspices/shipyard`, `SoulFireMage/starship-builder`,
`sito8943/sito-ship`, `a1studmuffin/SpaceshipGenerator`) делают sci-fi корабли из
примитивов. Мы не соревнуемся за «красивый один корабль» — там выигрывает
одноразовый промт. Мы держим то, чего у них нет: парусный астральный флот,
фракционные школы конструкции, смету, палитру-каналы, детерминизм и вызов из CLI.
Разбор: `docs/engine-rationale.md`.

| Блюпринт | `engine/spec.ts` | `ShipBlueprint`, `mergeBlueprint`, `describeBlueprint` |

| Посадка | `engine/mount.ts` | `probeHullSurface`, `mountFlush`, `scatterOnHull` |

## 4. Контракты данных

### 4.1 Блюпринт

```ts
type ShipBlueprint = {
  faction: 'league' | 'empire' | 'ork' | 'goblin' | 'neutral';
  classId: 'sloop' | 'frigate' | 'galleon' | 'dreadnought' | 'ram' | 'crab';
  seed: number;
  bow?: string; stern?: string; engine?: string;   // id части или пусто
  deck?: string[];                                  // накладки на палубу
  sails?: SailPlanId;                               // 'none' | 'squareRig' | 'petalFan' | ...
  masts?: number;                                   // 0..4
  gunRows?: 1 | 2;
  palette?: Partial<Record<ChannelName, number>>;
};
```

Приоритет источников: явный блюпринт → флаги CLI → разобранный текст → школа/класс.

### 4.2 Смета

`rulesForScale(scale)`: `maxSize` = 1 при `<0.85`, 2 при `<1.15`, иначе 3;
`maxMass = round((3 + scale * 4) * 10) / 10`. Ошибки: неизвестная часть, чужой
слот, перебор типоразмера, вместимости, массы. Пустой слот — предупреждение.
Сборка с ошибкой не собирается.

### 4.3 Палитра

Каналы: `hull, deck, trim, sail, glass, core, dark, lamp, wood`. Красится только
заданный канал, остальные остаются как были. Слова-краски: алый, ледяной,
золотой, кислотный, костяной, пустотный.

### 4.4 Поверхность

`probeHullSurface(hull, side, y, z)` → `{point, normal, along, side}` лучом из
`side*9` по `-side`; нормаль берётся из грани и разворачивается к борту.
`mountFlush` ставит объект по базису (касательная, нормаль, вбок). Средние
значения балки вместо луча запрещены: у борта есть завал.

## 5. Детерминизм

- Вся случайность — `rng` с сидом; `Math.random`, `Date.now`, порядок `Set` в
  генерации запрещены.
- Подпись: `faction|school|class|length|beam|...|bow|stern|engine|deck|sails`.
- Гарантия: один сид + фракция + класс → та же подпись, тот же меш, тот же GLB.
- Проверка: `lib/game/ship-engine.test.ts` + повторная сборка в CLI.

## 6. CLI (контракт для агента)

```powershell
npm run ship -- --text "имперский дредноут без парусов, сид 12" `
  --out shots/x.png --glb shots/x.glb --spec shots/x.json
```

| Флаг | Смысл |
|---|---|
| `--text` | описание словами |
| `--faction/--class/--seed` | явные параметры, сильнее текста |
| `--view` | `three-quarter/side/front/top` |
| `--size` | `1280x800` |
| `--background` | `#0b1224` или `none` |
| `--out/--spec/--glb` | PNG, JSON, GLB |
| `--tex` | сторона карт в GLB: 1024 по умолчанию, 512/256 — лёгкий файл |

stdout — JSON: `ok`, `out`, `glbBytes`, `errors`, `dna.signature`, `meshes`,
`barrels`, `hullColor`, `parsed`. Коды: 0 — годно, 1 — ошибки страницы,
2 — нет аргументов, 3 — нет playwright.

## 7. Качество поверхностей (приоритет 1)

Сделано 13.11: нормали считаются из карты высот (Sobel) вместо `bumpMap`; карты
шероховатости у лака, стали, латуни; CC0-сканы ambientCG (сталь, дерево, металл)
лежат в `public/textures` с манифестом `pack.json` — если файла нет, включается
процедурка. Проверка: `meanB` нормалей 0.94, разброс `R/G` 0.28, GLB несёт карты.

Осталось:

- критерий приёмки: у карты нормалей `B` в среднем > 0.9, `R/G` имеют разброс
  (не плоские), на кадре нет ошибок консоли, GLB несёт те же изображения.

Сделано 14.11: поверхности школ. У Орков борт — ржавые листы внахлёст со
светлым валиком сварки, у Гоблинов — кость с порами и прожилками, у Лиги лак,
у Империи плиты. Выбор идёт по `style.hullTexture`, материал корпуса получает
имя `hull:<школа>`: в GLB видно `hull:scrap`, `hull:bone`, `hull:lacquer` —
это и есть проверка, что школа доехала до экспорта.

Сделано 14.11: парус садится на рею. Их было две — широкая от мачты и короткая
внутри полотна, вторая торчала из паруса; оставили широкую, полотно висит ровно
с неё. Витрина: мешей 5254 вместо 5293 (минус 39 — по одной лишней рее на
мачту), стволов и подписей столько же.

Сделано 14.11: порт в борту. Дыра и латунный кант стояли на 10–12 см ниже оси
ствола, ствол выходил над портом. Теперь порт, кант и ствол на одной оси, и
витрина это проверяет: в аудите `probes[].portGap` у всех 20 бортов `0`.

Сделано 14.11: вес GLB. Цветные карты уходят в JPEG (нормали и шероховатость
остаются PNG — в рельефе сжатие видно), появился `--tex`. Дредноут Империи:
12,4 МБ было, 7,7 МБ при 1024, 1,7 МБ при 512. Внутри GLB 8 изображений,
4 материала с картами, размеры 256/512 совпадают с флагом.

## 8. Открытая упаковка (приоритет 2)

- Лицензия MIT (есть), README с быстрым стартом, `SUPPORT.md`.
- Отдельный публичный репозиторий движка: `lib/three/ship` + `tools` + примеры.
- npm-пакет с peer-зависимостью `three`, экспорт `generateShip`, `parseShipText`,
  `evaluateBuild`, `applyPalette`, `mountFlush`.
- Донаты: GitHub Sponsors + Boosty; ссылки даёт человек, не выдумываются.

Сделано 14.11: репозиторий https://github.com/aleksvega/astral-shipyard
(публичный, 23 файла движка, 11 тестов, CLI). Сборка — один ESM-файл 99 КБ,
чтобы `dist` не зависел от расширений в импортах. `npm publish` принят, но
реестр держит новое имя на подтверждении: под `astral-shipyard` пока заглушка
`0.0.0-stage`, версия 0.1.0 не видна до одобрения. Движок больше не тянет
`lib/game`: три общих типа объявлены локально.

Если за два месяца движок не использовал никто снаружи — он остаётся внутренним
модулем игры, отдельный продукт не делается. Донаты — следствие полезности, не
цель.
